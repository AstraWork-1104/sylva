# Flora - актуальные инструкции репозитория

## Актуальный контекст рабочего плагина Flora - 26.10.2026

Это описание десктопной Flora на Python/PySide6, а не утверждение о наличии перечисленных функций в HTML/JS этой ветки. Браузерная карта UI_MAP.md продолжает описывать только фактически существующий веб-код.

В Settings → Library → Library Paths подключаются несколько корневых библиотек .max, объединённых в один индекс моделей. Постоянная вкладка Explorer отображает все библиотеки. По правой кнопке на любой папке FOLDERS доступно Open in New Tab: дополнительная вкладка располагается непосредственно после существующих папочных вкладок и фильтрует общий индекс по полному нормализованному пути папки и её подпапок, без повторного обхода диска, копирования моделей или отдельного индекса.

Папочные вкладки располагаются слева от Catalogs, Scene, Favorites, Basket; при повторном открытии того же пути активируется существующая вкладка. Каждая вкладка хранит свои выбранную папку, поиск, фильтры и прокрутку; открытые вкладки восстанавливаются после перезапуска. Дерево дополнительной вкладки не повторяет её собственный корень, но модели непосредственно в нём доступны; вложенность дочерних папок выражается отступами при одинаковом размере шрифта. Закрывающие крестики компактные, отдельная кнопка добавления вкладки не используется.

Library Paths оформляется с отчётливым выделением строки, колонками Name / Root path и читаемыми длинными путями. Диалоги Add Folder и Edit Library в палитре Flora содержат Name, Root path, обзор папки и Cancel / Save. Diagnostics предоставляет Open log и Copy log. Подробные функциональные решения содержатся в основном документе Flora в Google Docs; изменение этих пояснений не изменяет HTML-макет.

## Действующий дизайн

Ветка `flora-ui-v2`, папка `flora-ui/` - утверждённый визуальный референс. Сверяйте исходники `index.html`, `styles.css`, `app.js`; `Flora-UI.html` - автономная упаковка того же прототипа. Не использовать другие ветки и старые README как источник новых требований. GitHub доступ и официальные технические справочники разрешены по необходимости.

HTML/JS - визуальная демонстрация, а НЕ работающий плагин Autodesk 3ds Max. Настоящая Flora реализована на Python/PySide6/MAXScript, реальные данные - из индексированной .max-библиотеки и SQLite FloraAtlas v1. При переносе в PySide6 сохранять функционирующие Explorer, Favorites, Basket, Catalogs/FloraCOL, Drag & Drop, Corona Proxy/Merge, материалы и пользовательские настройки.

## Предыдущий UI-цикл после 1.0.0.44 (22.10.2026)

В ПРЕДЫДУЩЕМ цикле Codex переданы **две UI-постановки**. **Уточняющий таск на масштабирование шрифта, кнопки навигации/«Фильтры», выравнивание поиска и удаление строки пути Explorer выполнен и принят владельцем 22.10.2026**. Самый новый корректирующий таск следующего цикла §21 пока НЕ подтверждён выполнением. Более ранний комплексный UI-таск не считать целиком принятым только на основании этого сообщения. Номер новой версии и commit пока не сообщены. В рабочем PySide6 Properties **View** остаётся компактным, секционные заголовки «Названия», «Ботанические сведения», «Описание» унифицируются и не имеют стрелок сворачивания; **Edit** - полноширинная вертикальная форма с подписями над полями; input/textarea визуально отличны от single-select; Natural/Home выбираются видимыми чекбоксами в две колонки без внутренней прокрутки. Все Qt single-select получают общий контрастный popup, читаемые строки и корректную геометрию. Размеры иконко-текстовых кнопок (включая Explorer/Catalogs/Scene/Favorites/Basket и «Фильтры») динамически зависят от шрифта Settings, без наложений и обрезания. В Filters убрать лишний подзаголовок «Среда»; в Explorer не показывать отдельную строку абсолютного пути под заголовком, поднять поиск; две правые кнопки в строке поиска равнять по высоте с полем поиска. В Basket вместо постоянно видимого ползунка - общая кнопка Tile Size с popup; общий заголовок и строка управления размещаются на всю ширину НАД Properties.

Прежние требования «сворачиваемые заголовки Properties» и «неизменная двухколоночная Edit-форма» **заменены** поздним решением. Эти Qt-требования нельзя считать реализованными в HTML-макете только потому, что они описаны здесь. Подробности - [§20 основного описания Flora](https://docs.google.com/document/d/19MQLTbmyikvPj2wCLwIvuSqF3sdwJ8YUlSEtsMSkbZ0/edit).

## Визуальный стиль

Сохранять спокойный тёмно-зелёный плоский дизайн без глянца, рельефа и выпуклых кнопок. Сохранять адаптивность, корректное выделение и прокрутку. Не генерировать изображения вместо редактирования реальных UI-файлов. При изменении CSS/JS синхронизировать `Flora-UI.html`, проверить JavaScript и отсутствие устаревших декоративных стилей.

## Актуальная классификация и Filters

Реализованное в браузерном дизайне поведение Filters: `Группа растения` (Все группы, Деревья, Кусты, Трава) -> зависимая `Категория растения` (недоступна до выбора группы); `Тип среды` (Все среды, Природные, Домашние) -> зависимая `Категория среды` (недоступна до выбора типа); `Цветение` (Все, Да, Нет); `Высота, см` (неактивные От/До до точного анализа). Категории групп: Деревья - Лиственные, Хвойные, Пальмы; Кусты - Лиственные, Хвойные, Папоротники, Злаки, Вьющиеся, Многолетники, Суккуленты; Трава - Травы, Цветы, Почвопокровные, Луковичные. Природные среды: Лесная, Луговая, Водная, Прибрежная, Степная, Пустынная, Горная; Домашние: Улицы, Парки, Сады, Дворы, Интерьеры. Родительский выбор сбрасывает дочерний. Компоновка автоматически 4/2/1 колонка по ширине центральной панели с собственной вертикальной прокруткой при уменьшении высоты.

В SQLite `natural_json` и `landscaped_json` остаются массивами нескольких значений; «Домашние» - историческая подпись в браузерном HTML, в утверждённом Qt UI это Landscaped, без переименования `landscaped_json`. `similar_json` - массив связанных `plant_id` растений из того же Atlas. Ботанический FloraCat больше не использовать, тематический FloraCOL сохранять.

## Дополнительно согласованные изменения для рабочего плагина

Без настройки видимости/порядка полей: фиксированный набор полей Properties. Исторически секции «Названия»/«Ботанические сведения» были раскрываемыми; действующее решение владельца для PySide6 убирает стрелки сворачивания и задаёт три английских заголовка Names, Information, Description (§21), при сохранении русских фактических значений категорий. Grid: модель, под ней русское и английское названия при наличии, без Vol. Table: только актуальные RU/EN/Latin, цветение, группа/категория, тип/категория среды. Поиск: filename, RU/EN/Latin и названия связанных похожих растений. Settings: очистка импортированных метаданных/каталогов с подтверждением и сохранением Favorites, коллекций, библиотеки, сцены и исходных файлов.

**Различать статусы:** многие из этих элементов уже представлены в веб-макете; это не доказывает их реализацию в 3ds Max. Для HTML сверять UI_MAP.md/фактический код, для рабочего плагина - его текущие исходники и host-проверки. Не возвращать Scatter или пакетную автоматическую генерацию превью.

## Экономия контекста при задачах Codex

Задача Codex должна включать все согласованные требования, точные подписи и состояния UI (включая неактивные селекторы, поиск, счётчики, карточки и множественные значения), границы очистки/сохранения пользовательских данных и проверяемые критерии. Архитектор ИНИЦИАТИВНО проверяет полноту и риски, предлагает оптимальную организацию: одну комплексную задачу, логические этапы в одном запуске либо отдельные задачи по реальным зависимостям и безопасности. Не устанавливать универсальное число этапов, лимит ссылок, длину задания, объём технического поиска или тестов. Цель - минимальный СОВОКУПНЫЙ расход на корректное исполнение без регрессий и переделок, а не самый короткий текст. Filters/Properties/Grid/Table/Search могут рационально разделять один анализ FloraAtlas; опасная очистка импортированных данных может требовать отдельного контрольного этапа. Это примеры, не обязательное дробление. Не требовать автоматически читать все ссылки подряд: актуальную локальную FLORA_CODEMAP.md использовать для адресной навигации по рабочим функциям, UI V2 - только для конкретного визуального примера, SQLite-спецификацию - по необходимости. Не вводить обязательную перепроверку только что обновлённой карты или аудит без конкретной причины. Codex свободен выбирать кодовую архитектуру и технические решения, а также пользоваться интернетом, GitHub и целевыми тестами. Архитектор проверяет текст задания до передачи, но не навязывает пользователю отдельный отчёт о самопроверке.

## Банк будущих идей не является ТЗ

Не переносить идеи из банка в браузерный макет, рабочий код или текущие инструкции автоматически.
