# Flora - актуальные инструкции репозитория

## Действующий дизайн

Ветка `flora-ui-v2`, папка `flora-ui/` - утверждённый визуальный референс. Сверяйте исходники `index.html`, `styles.css`, `app.js`; `Flora-UI.html` - автономная упаковка того же прототипа. Не использовать другие ветки и старые README как источник новых требований. GitHub доступ и официальные технические справочники разрешены по необходимости.

HTML/JS - визуальная демонстрация, а НЕ работающий плагин Autodesk 3ds Max. Настоящая Flora реализована на Python/PySide6/MAXScript, реальные данные - из индексированной .max-библиотеки и SQLite FloraAtlas v1. При переносе в PySide6 сохранять функционирующие Explorer, Favorites, Basket, Catalogs/FloraCOL, Drag & Drop, Corona Proxy/Merge, материалы и пользовательские настройки.

## Статус рабочего плагина Flora 1.0.0.44 (20.10.2026)

По отчёту Codex готова сборка **1.0.0.44**, commit `6a382cd`. В ней исправлено оформление редакторов Properties (без изменения Save/Cancel и SQLite overrides), добавлена Scene с `FloraSource`, `×N`, Select Model и placeholder отсутствующих исходников, обновлена навигация Explorer слева / Catalogs → Scene → Favorites → Basket справа **с иконками и видимыми подписями**, зелёная галочка Scene Presence заменена **маленькой зелёной точкой**. Qt-тесты и регрессии импорта, Cache, Basket и lifecycle прошли **вне 3ds Max**. Исторический отчёт упоминает проверки Scene, Select Model, обновления после удаления объектов и Reset; Reset не следует автоматически включать в новые UI-таски. Это не означает пользовательскую приёмку сборки.

Settings не переделывали в рамках последнего набора правок. Ранее обсуждавшиеся Instance Import, Uninstall и изменения Filters остаются отдельными требованиями, а не подтверждёнными возможностями 1.0.0.44. GitHub UI V2 - лишь веб-референс, а не код рабочего PySide6. Исторический релиз описан в [разделе 19 основного описания Flora](https://docs.google.com/document/d/19MQLTbmyikvPj2wCLwIvuSqF3sdwJ8YUlSEtsMSkbZ0/edit).

## Новейшие утверждённые UI-решения после 1.0.0.44 (22.10.2026)

Утверждены и переданы Codex **две UI-постановки**. **Последний отдельный таск на масштабирование шрифта, кнопки навигации/«Фильтры», выравнивание строки поиска и удаление пути Explorer выполнен и принят владельцем 22.10.2026**. Более ранний комплексный UI-таск не считать целиком принятым только на основании этого сообщения. Номер новой версии и commit пока не сообщены. В рабочем PySide6 Properties **View** остаётся компактным, секционные заголовки «Названия», «Ботанические сведения», «Описание» унифицируются и не имеют стрелок сворачивания; **Edit** - полноширинная вертикальная форма с подписями над полями; input/textarea визуально отличны от single-select; Natural/Home выбираются видимыми чекбоксами в две колонки без внутренней прокрутки. Все Qt single-select получают общий контрастный popup, читаемые строки и корректную геометрию. Размеры иконко-текстовых кнопок (включая Explorer/Catalogs/Scene/Favorites/Basket и «Фильтры») динамически зависят от шрифта Settings, без наложений и обрезания. В Filters убрать лишний подзаголовок «Среда»; в Explorer не показывать отдельную строку абсолютного пути под заголовком, поднять поиск; две правые кнопки в строке поиска равнять по высоте с полем поиска. В Basket вместо постоянно видимого ползунка - общая кнопка Tile Size с popup; общий заголовок и строка управления размещаются на всю ширину НАД Properties.

Прежние требования «сворачиваемые заголовки Properties» и «неизменная двухколоночная Edit-форма» **заменены** поздним решением. Эти Qt-требования нельзя считать реализованными в HTML-макете только потому, что они описаны здесь. Подробности - [§20 основного описания Flora](https://docs.google.com/document/d/19MQLTbmyikvPj2wCLwIvuSqF3sdwJ8YUlSEtsMSkbZ0/edit).

## Визуальный стиль

Сохранять спокойный тёмно-зелёный плоский дизайн без глянца, рельефа и выпуклых кнопок. Сохранять адаптивность, корректное выделение и прокрутку. Не генерировать изображения вместо редактирования реальных UI-файлов. При изменении CSS/JS синхронизировать `Flora-UI.html`, проверить JavaScript и отсутствие устаревших декоративных стилей.

## Актуальная классификация и Filters

Реализованное в браузерном дизайне поведение Filters: `Группа растения` (Все группы, Деревья, Кусты, Трава) -> зависимая `Категория растения` (недоступна до выбора группы); `Тип среды` (Все среды, Природные, Домашние) -> зависимая `Категория среды` (недоступна до выбора типа); `Цветение` (Все, Да, Нет); `Высота, см` (неактивные От/До до точного анализа). Категории групп: Деревья - Лиственные, Хвойные, Пальмы; Кусты - Лиственные, Хвойные, Папоротники, Злаки, Вьющиеся, Многолетники, Суккуленты; Трава - Травы, Цветы, Почвопокровные, Луковичные. Природные среды: Лесная, Луговая, Водная, Прибрежная, Степная, Пустынная, Горная; Домашние: Улицы, Парки, Сады, Дворы, Интерьеры. Родительский выбор сбрасывает дочерний. Компоновка автоматически 4/2/1 колонка по ширине центральной панели с собственной вертикальной прокруткой при уменьшении высоты.

В SQLite `natural_json` и `landscaped_json` остаются массивами нескольких значений; «Домашние» - имя UI для `landscaped_json`. `similar_json` - массив связанных `plant_id` растений из того же Atlas. Ботанический FloraCat больше не использовать, тематический FloraCOL сохранять.

## Дополнительно согласованные изменения для рабочего плагина

Без настройки видимости/порядка полей: фиксированный набор полей Properties. Исторически секции «Названия»/«Ботанические сведения» были раскрываемыми; действующее решение владельца для PySide6 убирает стрелки сворачивания и унифицирует три заголовка «Названия», «Ботанические сведения», «Описание». Grid: модель, под ней русское и английское названия при наличии, без Vol. Table: только актуальные RU/EN/Latin, цветение, группа/категория, тип/категория среды. Поиск: filename, RU/EN/Latin и названия связанных похожих растений. Settings: очистка импортированных метаданных/каталогов с подтверждением и сохранением Favorites, коллекций, библиотеки, сцены и исходных файлов.

**Различать статусы:** многие из этих элементов уже представлены в веб-макете; это не доказывает их реализацию в 3ds Max. Для HTML сверять UI_MAP.md/фактический код, для рабочего плагина - его текущие исходники и host-проверки. Не возвращать Scatter или пакетную автоматическую генерацию превью.

## Ответственность и передача результатов

Пользователь утверждает продуктовые решения. Отдельный чат-архитектор помогает с требованиями и по запросу формулирует задания Codex, но не берёт на себя код, математические алгоритмы и сборку. Codex исследует рабочие локальные исходники, сам выбирает технический способ реализации, проверяет и сохраняет результат в привычную ЛОКАЛЬНУЮ папку пользователя. Административный чат поддерживает Google-документы; его одобрение каждого задания не требуется. Файлы, создаваемые самим ChatGPT, пользователь предпочитает получать с Google Диска. Не вводить по умолчанию обязательные Issues/PR, CI/CD или загрузку сборок в облако.

Инструкция для чата-архитектора: https://docs.google.com/document/d/1Ohlf7RkIipPuNebNaDxLjsZ6TSHqbooHe0jdwukpR6g/edit

Его зона - `flora-ui/index.html`, `styles.css`, `app.js`, синхронизация автономного `Flora-UI.html` и профильных `README.md`, `docs/DESIGN.md`, `docs/SCREENS.md`. ## Экономия контекста при задачах Codex

Задача Codex должна включать все согласованные требования, точные подписи и состояния UI (включая неактивные селекторы, поиск, счётчики, карточки и множественные значения), границы очистки/сохранения пользовательских данных и проверяемые критерии. Архитектор ИНИЦИАТИВНО проверяет полноту и риски, предлагает оптимальную организацию: одну комплексную задачу, логические этапы в одном запуске либо отдельные задачи по реальным зависимостям и безопасности. Не устанавливать универсальное число этапов, лимит ссылок, длину задания, объём технического поиска или тестов. Цель - минимальный СОВОКУПНЫЙ расход на корректное исполнение без регрессий и переделок, а не самый короткий текст. Filters/Properties/Grid/Table/Search могут рационально разделять один анализ FloraAtlas; опасная очистка импортированных данных может требовать отдельного контрольного этапа. Это примеры, не обязательное дробление. Не требовать автоматически читать все ссылки подряд: актуальную локальную FLORA_CODEMAP.md использовать для адресной навигации по рабочим функциям, UI V2 - только для конкретного визуального примера, SQLite-спецификацию - по необходимости. Не вводить обязательную перепроверку только что обновлённой карты или аудит без конкретной причины. Codex свободен выбирать кодовую архитектуру и технические решения, а также пользоваться интернетом, GitHub и целевыми тестами. Архитектор проверяет текст задания до передачи, но не навязывает пользователю отдельный отчёт о самопроверке.

## Банк будущих идей не является ТЗ

В Flora есть отдельный [чат для обсуждения идей](https://docs.google.com/document/d/1Mng_1SV5dMVfvmmIGSxgQuhuygOTvBhoYErMXMdKNyw/edit) и единый [банк будущих идей на Google Диске](https://docs.google.com/document/d/1UTZxVykKj0NNn96CyqdUP4J150iBLgFWgkrjnbFbbTg/edit). Записи туда добавляются только по явной просьбе пользователя. Они могут быть не утверждены, не исследованы и не включены в план разработки. Не переносить идеи из банка в браузерный макет, рабочий код или текущие инструкции автоматически. После согласования пользователем выбранной идеи архитектор прорабатывает требования; дизайнер обновляет UI только по утверждённому решению. Не нужно читать весь банк перед обычными правками.
